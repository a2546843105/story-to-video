# 完整工作流

## 目录与状态

以 `制作过程/` 为工作根目录：

```text
制作过程/
├── assets/
│   ├── characters/
│   ├── generated/
│   ├── props/
│   └── fonts/
├── audio/
├── captions/
├── compositions/scenes/
├── planning/
├── snapshots/
├── renders/
└── logs/
```

在 `planning/project-state.json` 记录：

- 输入文案哈希；
- 开工前置检查状态；
- 声音服务、非敏感凭据状态、音色、模型、响度、画幅和帧率；
- 当前阶段；
- 已批准的风格锚点；
- 固定人物白名单；
- 三个代表镜头是否通过；
- 每个场景范围的负责人和完成状态；
- 最近一次检查与渲染结果。

只从最后一个通过门槛的阶段恢复，不要整条流程重跑。

## 阶段

### 0. 开工前置检查

在生成旁白、图片、场景或派工之前，一次性确认：

1. 完整文案和交付目录；
2. 配音服务；
3. 服务是否需要 API 凭据，以及凭据是否已经可用；
4. 音色 ID、模型和目标响度；
5. 画幅、分辨率与帧率；
6. 豆包母图和其他风格参考。

若配音服务需要 API 而凭据不可用，立即询问用户并暂停生产，不要先用占位音频制作再返工时间轴。不得把密钥值写进项目状态、脚本、日志或 Git；状态文件只记录服务名称、凭据是否可用和非敏感参数。

将 `preflight.status` 设为 `approved` 后运行 `scripts/preflight_guard.ps1`。检查未通过时，只允许继续只读检查和规划。

### A. 文案与旁白

1. 原样保存用户文案为根目录 `文案.txt`。
2. 清理仅影响朗读的标点与空格，不改变叙事内容。
3. 生成旁白并保存原始版、响度处理版和最终混音版。
4. 先做时间戳转写，再按意思分镜。不要按固定字数机械切割。
5. 默认只制作一个完整成片；用户没有明确提出时，不另外拆分短版。

### B. 两套叙事

旁白负责说明事件；视觉对话负责补充态度、误解、嘴硬、反应和反差。

每个场景优先选择一种笑点：

- 角色把坏主意说得很正经；
- 角色对荒谬结果一本正经地接受；
- 观众知道真相，角色还在嘴硬；
- 画面道具揭穿旁白；
- 前文埋伏，后文回收；
- AI式客套话放在最不合适的场合。

对话通常控制在 4–14 个汉字。若必须解释才能看懂，重写笑点，不要扩大气泡。

### C. 场景清单

`scene_manifest.json` 的每一项至少包含：

```json
{
  "id": "scene-001",
  "start": 0.0,
  "end": 9.8,
  "narration": "旁白片段",
  "visual": "谁在什么地方做什么",
  "dialogue": "角色短对话",
  "characters": ["hero"],
  "assets": ["hero-thinking", "phone"],
  "motion": ["hero-enter", "phone-pop", "bubble-punch"]
}
```

先完成清单再生成图片，避免边做边改故事导致素材报废。

### D. 素材

1. 始终把 Skill 内置的 `assets/characters/doubao-mother.png` 作为豆包身份母图。
2. 生成豆包的任何姿势、服装变化或表情时都必须同时提交母图作为图片参考；提示词只描述需要变化的动作、服装和场景，不重新描述或重造脸。
3. 其他人物只需参考豆包母图的漫画渲染方式、描边和精细程度，不要复制豆包的脸。其他人物跨作品不要求固定；同一篇故事再次出现时引用最近一张正确画面。
4. 一张生成图放 2–3 个大素材，彼此分离，轮廓清晰。
5. 透明人物先保留 2 px 牺牲白边，再向内裁掉 1 px，最终留下约 1 px 干净白边。
6. 裁剪后立即在透明底、浅色底和深色底生成联系表，检查残肢、漏底、重叠和红紫色边缘，不等到进入视频才发现问题。

### E. 版式冻结

批量制作前把版式写成共享变量或组件，不允许每幕各自猜尺寸。1920×1080 默认：

- 主人物可见高度约占画面 45–55%；
- 配角可见高度约占 38–50%；
- 分属不同区域的人物之间至少留 40 px；
- 底部 170 px 只放旁白字幕；
- 人脸、手、人物轮廓、气泡和关键信息不得互压。

三个代表镜头必须共同覆盖单人物、多人同框和人物加 UI/卡片遮罩；若三幕无法覆盖，增加一个代表镜头。只有白边、人物比例、间距和遮挡全部通过后，才冻结版式并开始并行。

### F. 动画

每个镜头至少包含三个阶段：

1. 进入：滑入、弹入、揭示或遮罩；
2. 反应：人物轻移、转头、抖动、道具动作或文字击打；
3. 停留与退出：给观众读完对话的时间，再自然切走。

保持 seek-safe；用时间轴驱动，不依赖不可控的实时动画。

### G. QA 与渲染

按以下顺序执行：

1. 代表镜头的白边、人物比例、40 px 间距和 UI 遮挡检查；
2. 三段批量联系表；
3. 视觉规则脚本；
4. HyperFrames lint/check；
5. 整片入口抽最后一幕三帧；
6. 低码率草稿；
7. 正式渲染；
8. 最终视频16帧联系表；
9. 全片解码、响度和交付目录验证。

发现系统性错误时先修代表镜头和模板，再重新批量；不要在几十个场景里逐个打补丁。
