# 完整工作流

## 目录与状态

以 `制作过程/` 为工作根目录：

```text
制作过程/
├── assets/
│   ├── characters/
│   ├── generated/
│   ├── props/
│   └── fonts/
├── audio/
├── captions/
├── compositions/scenes/
├── planning/
├── snapshots/
├── renders/
└── logs/
```

在 `planning/project-state.json` 记录：

- 输入文案哈希；
-声音、响度、画幅和帧率；
- 当前阶段；
- 已批准的风格锚点；
- 固定人物白名单；
- 三个代表镜头是否通过；
- 每个场景范围的负责人和完成状态；
- 最近一次检查与渲染结果。

只从最后一个通过门槛的阶段恢复，不要整条流程重跑。

## 阶段

### A. 文案与旁白

1. 原样保存用户文案为根目录 `文案.txt`。
2. 清理仅影响朗读的标点与空格，不改变叙事内容。
3. 生成旁白并保存原始版、响度处理版和最终混音版。
4. 先做时间戳转写，再按意思分镜。不要按固定字数机械切割。

### B. 两套叙事

旁白负责说明事件；视觉对话负责补充态度、误解、嘴硬、反应和反差。

每个场景优先选择一种笑点：

- 角色把坏主意说得很正经；
- 角色对荒谬结果一本正经地接受；
- 观众知道真相，角色还在嘴硬；
- 画面道具揭穿旁白；
- 前文埋伏，后文回收；
- AI式客套话放在最不合适的场合。

对话通常控制在 4–14 个汉字。若必须解释才能看懂，重写笑点，不要扩大气泡。

### C. 场景清单

`scene_manifest.json` 的每一项至少包含：

```json
{
  "id": "scene-001",
  "start": 0.0,
  "end": 9.8,
  "narration": "旁白片段",
  "visual": "谁在什么地方做什么",
  "dialogue": "角色短对话",
  "characters": ["hero"],
  "assets": ["hero-thinking", "phone"],
  "motion": ["hero-enter", "phone-pop", "bubble-punch"]
}
```

先完成清单再生成图片，避免边做边改故事导致素材报废。

### D. 素材

1. 始终把 Skill 内置的 `assets/characters/doubao-mother.png` 作为豆包身份母图。
2. 生成豆包的任何姿势、服装变化或表情时都必须同时提交母图作为图片参考；提示词只描述需要变化的动作、服装和场景，不重新描述或重造脸。
3. 其他人物只需参考豆包母图的漫画渲染方式、描边和精细程度，不要复制豆包的脸。其他人物跨作品不要求固定；同一篇故事再次出现时引用最近一张正确画面。
4. 一张生成图放 2–3 个大素材，彼此分离，轮廓清晰。
5. 裁剪后立即生成联系表检查，不等到进入视频才发现残肢。

### E. 动画

每个镜头至少包含三个阶段：

1. 进入：滑入、弹入、揭示或遮罩；
2. 反应：人物轻移、转头、抖动、道具动作或文字击打；
3. 停留与退出：给观众读完对话的时间，再自然切走。

保持 seek-safe；用时间轴驱动，不依赖不可控的实时动画。

### F. QA 与渲染

按以下顺序执行：

1. 三个代表镜头联系表；
2. 三段批量联系表；
3. 视觉规则脚本；
4. HyperFrames lint/check；
5. 整片入口抽最后一幕三帧；
6. 低码率草稿；
7. 正式渲染；
8. 最终视频16帧联系表；
9. 响度和交付目录验证。

发现系统性错误时先修代表镜头和模板，再重新批量；不要在几十个场景里逐个打补丁。
