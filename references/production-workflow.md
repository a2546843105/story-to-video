# 生产流程

## 1. 建立任务

创建独立目录，至少包含：

```text
inputs/
audio/
prompts/
images/
composition/
qa/
renders/
script.txt
style_spec.json
shot_timeline.json
```

把用户本次文案和参考图复制到 `inputs/`。记录来源，不修改原件。

## 2. 锁定文案

- 将用户确认版本保存为 `script.txt`。
- 不润色、不补情节、不改观点；发现明显漏字只报告，不擅自修复。
- 标记章节、逻辑转折、时间跨度、人物关系、地点、关键物件、数字、因果和结尾回响。

## 3. 生成旁白

- 使用用户指定的声音、供应商、语速和情绪；未指定时选择适合题材的稳定中文叙述声。
- 长文分段生成后无缝拼接，去除异常停顿、重复句和漏句。
- 整轨目标约 `-16 LUFS`，真峰值不高于 `-1 dBTP`。
- 从最终音频转写出词级或句级时间戳。后续一切时长以最终音频为准。

## 4. 建立镜头时间轴

- 默认每分钟 5–7 张图，通常每张 7–14 秒。
- 在段落转折、地点变化、人物阶段、关键证据、数字结论和情绪落点处换图。
- 不逐句配图；一张图可以承载相邻两三句话。
- 同一长段可用全景和局部特写拆成两个镜头，但避免连续重复。
- 每个镜头记录：
  - `id`
  - `start_s`
  - `end_s`
  - `narration`
  - `visual_function`
  - `subjects`
  - `setting`
  - `prompt`
  - `motion`
  - `transition`

## 5. 生成图片

- 每个提示词都携带本次参考图，并重申 `style_spec.json` 中最重要的视觉特征。
- 只有需要持续角色一致性时才锁定角色；技术、金融、历史和抽象话题不要凭空塞入固定主角。
- 每批最多 10 张，保持镜头编号不变。
- 每批完成后核对张数并生成接触表，检查：
  - 题意是否正确；
  - 画风是否漂移；
  - 角色、时代、服装和道具是否一致；
  - 手脚、文字、水印、Logo 和重复人物是否异常；
  - 16:9 构图与字幕安全区是否合理。

## 6. 组装视频

- 旁白从 0 秒开始。
- 片头与旁白重叠，不为动画延迟正文。
- 普通图片使用 2%–5% 的缓慢缩放，或小幅单向位移。
- 普通换图直接切换或使用 0.25–0.45 秒叠化。
- 重要章节可以使用更明确的擦除、横缝或快速预览，但持续时间要短。
- 字幕放在安全区，避免遮住关键面部、数字或图表。
- 默认不添加片头音效、正文音效和高存在感 BGM。

## 7. 发布素材

每次都按 `publishing-package.md` 生成：

- 3:4 竖版封面；
- 4:3 横版封面；
- 可直接发布的最终标题、简介和话题标签。

双封面使用同一套主题、角色和视觉语言，但分别重新构图，不把一张图机械裁成另一个比例。发布文案必须来自本次文案，不套用其他项目的标题和标签。

## 8. 质量检查

1. 运行 HyperFrames `check`。
2. 抽查片头、前 3 张图、中段、结尾和所有明显转场。
3. 渲染后从实际 MP4 再抽帧，确认预览与成片一致。
4. 检查旁白完整、字幕同步、画面顺序、黑帧、闪烁和音轨。
5. 检查两张封面的尺寸、主体、文字、安全区和缩略图可读性。
6. 检查标题不超过 30 个字符，简介与话题没有无关热点或事实夸张。
7. 生成平台上传版并验证文件。
